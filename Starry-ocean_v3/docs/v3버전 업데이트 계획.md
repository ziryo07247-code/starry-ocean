# Starry-Ocean 버전 업데이트 계획

## 1. 업데이트 방향

Starry-Ocean은 기존 기능을 단순히 추가하는 방식이 아니라,

> **기능 개선 → 데이터 실험 → 성능 분석 → 최적값 도출 → 실제 기능 반영 → AI 기술 비교 → 서비스 확장**

순서로 발전시킨다.

또한 모든 기능과 기술 선택은 **사용자 경험(UX)을 중심으로 결정**한다.

AI가 많은 정보를 분석하더라도 사용자가 이해하기 어렵거나 화면이 복잡해진다면 모든 정보를 그대로 표시하지 않고, 사용자가 필요한 정보를 단계적으로 확인할 수 있도록 설계한다.

# Starry-Ocean v2 — 기본 AI 메모 시각화 서비스

현재까지 개발한 Starry-Ocean의 기본 기능을 안정화하고 AI 기반 메모 시각화 서비스를 완성한다.

### 주요 기능

- 메모 CRUD
- 구역(Island) 관리
- 메모 별 시각화
- AI 임베딩
- 메모 유사도 분석
- AI 자동 배치
- 메모 이동
- 별자리 연결
- 미니맵
- 메모 모달
- 기본적인 예외처리
- Node.js + Express + MySQL 기반 서버

v2의 목표는 **"기본적인 AI 메모 시각화 서비스가 정상적으로 동작하는 상태"**로 정의한다.

## v3.1 — UX/UI 개선 및 사용성 강화

### 1. 튜토리얼 기능

처음 서비스를 이용하는 사용자를 대상으로 Starry-Ocean의 주요 기능과 사용 방법을 설명한다.

- 서비스 기본 개념
- 메모 작성 방법
- AI 분석 방법
- 별과 구역의 관계
- 메모 이동 방법
- AI 자동 배치 기능
- Tree 메뉴 사용 방법
- 연결선 및 AI 관계 표시 방법

### 2. 별(메모) 이름 표시

기존에는 메모가 별 형태로 표시되었다면, 별이 생성될 때 메모의 이름 또는 제목을 바로 확인할 수 있도록 개선한다.

목표:

- 별을 클릭하지 않아도 메모 구분
- 많은 메모를 쉽게 탐색
- 원하는 메모를 빠르게 찾을 수 있도록 개선

### 3. 구역 이름 표시

각 구역의 이름을 화면에 간단하게 표시한다.

표시 위치를 여러 방식으로 테스트한다.

- 왼쪽 상단
- 오른쪽 상단
- 왼쪽 하단
- 오른쪽 하단
- 구역 중앙

최종적으로 화면을 가리지 않으면서 사용자가 현재 위치를 쉽게 인식할 수 있는 위치를 선정한다.

### 4. Tree형 보조 메뉴

화면 왼쪽에 보조 메뉴를 추가하여 구역별 메모 목록을 Tree 구조로 표시한다.

```text
Starry-Ocean
├── 구역 1
│   ├── 메모 A
│   ├── 메모 B
│   └── 메모 C
├── 구역 2
│   ├── 메모 D
│   └── 메모 E
└── 구역 3
    ├── 메모 F
    └── 메모 G
```

기능:

- 구역별 메모 확인
- 메모 선택 시 해당 별 위치로 이동
- 구역 선택 시 해당 구역으로 이동
- 대량 메모 탐색 지원

### 5. 메모 저장 + AI 분석 통합

기존:

```text
메모 작성
→ 저장
→ AI 분석 버튼
→ 분석
→ 별 생성
```

개선:

```text
메모 작성
→ 저장 및 AI 분석
→ 별 생성 및 배치
```

기존 방식과 통합 방식의 다음 항목을 비교한다.

- 사용자의 조작 횟수
- 전체 처리시간
- API 호출 횟수
- 사용자 체감 대기시간
- 오류 발생 가능성

### 6. 연결선 UX 개선

메모 간 관계를 모두 표시하면 화면이 복잡해질 수 있으므로 사용자에게 필요한 관계만 단계적으로 표시한다.

기본:

```text
★       ★

    ★

       ★
```

별 선택:

```text
★────★
 \
  ───★
```

카테고리 선택:

```text
[회사]

★────★
│
└────★
```

AI 분석:

```text
[AI 관계 분석]

★──────★
│ ╲     │
│   ╲   │
★───────★
```

연결 관계의 종류를 구분하여 표시할 수 있도록 설계한다.

- 주제 관계
- 감정 관계
- 키워드 관계
- 시간 관계
- 의미 유사도 관계

단, 모든 연결선을 동시에 표시하지 않고 사용자가 원하는 관계를 선택하여 확인할 수 있도록 한다.

### 7. 예외처리 강화

- 빈 메모 입력
- 지나치게 긴 메모
- 잘못된 구역 ID
- 존재하지 않는 메모 ID
- DB 연결 오류
- AI 서버 오류
- 임베딩 생성 실패
- 중복 요청
- 네트워크 오류
- 잘못된 API 요청
- AI 분석 중 페이지 이탈

# v3.2 — 대용량 메모 데이터 실험

Starry-Ocean의 AI 자동 배치 및 임베딩 분석이 많은 메모에서도 정상적으로 동작하는지 검증한다.

## 1. 데이터셋 구성

다음과 같은 데이터 규모를 기준으로 실험한다.

- 10개
- 30개
- 50개
- 100개
- 200개
- 300개
- 500개

가능하면 실제 사용자가 작성할 법한 다양한 주제의 메모를 구성한다.

## 2. 성능 분석

각 데이터 규모에 대해 다음 항목을 측정한다.

### 서버 성능

- 전체 AI 분석 시간
- 임베딩 생성 시간
- DB 처리 시간
- API 응답 시간
- CPU 사용량
- Memory 사용량

### AI 분석 결과

- 생성 그룹 수
- 메모 연결 수
- 유사 메모 그룹 품질
- 관련 없는 메모 연결 비율
- 그룹별 메모 집중도

### 화면 사용성

- 별 겹침 정도
- 별 구분 가능 여부
- 화면 탐색 난이도
- 구역 과밀화
- Tree 메뉴 필요성
- 연결선 과다 표시 여부

# v3.3 — 최적 메모 개수 도출 및 구역 제한

v3.2의 실험 결과를 바탕으로 하나의 구역에서 사용자가 탐색하기 적절한 메모 개수를 결정한다.

## 분석 예시

| 메모 수 | 분석 시간 | 별 배치 | 화면 복잡도 | 사용성 |
| ------: | --------: | ------- | ----------- | ------ |
|      50 |      측정 | 양호    | 낮음        | 양호   |
|     100 |      측정 | 양호    | 보통        | 양호   |
|     200 |      측정 | 확인    | 높음        | 확인   |
|     300 |      측정 | 확인    | 매우 높음   | 낮음   |
|     500 |      측정 | 확인    | 매우 높음   | 낮음   |

※ 실제 수치는 실험 결과를 기록한다.

## 최적 메모 수 결정

실험 결과를 기반으로

> **한 구역에서 사용자가 탐색하기 가장 적절한 메모 개수**

를 결정한다.

예:

```text
최대 100개
```

또는

```text
최대 150개
```

## 실제 기능 반영

구역별 메모 개수를 표시한다.

```text
현재 구역 메모 87 / 100
```

제한에 가까워지면 경고한다.

```text
현재 구역에 메모가 거의 가득 찼습니다.
```

제한에 도달하면 다음 방법을 안내한다.

- 다른 구역으로 이동
- 새로운 구역 생성
- 기존 메모 정리

> **로컬 환경에서만 동작하던 Starry-Ocean을 실제 인터넷 환경에서 접근 가능한 서비스로 발전시킨다.**

# v4.5 — Node.js vs Spring Boot 비교

동일한 Starry-Ocean 기능을 Node.js와 Spring Boot로 각각 구현하여 비교한다.

## Node.js

```text
React
 ↓
Node.js + Express
 ↓
MySQL
 ↓
FastAPI
```

## Spring Boot

```text
React
 ↓
Spring Boot
 ↓
MySQL
 ↓
FastAPI
```

Frontend와 사용자 경험은 최대한 동일하게 유지하고 Backend 구조만 변경한다.

## 비교 항목

| 항목           | Node.js | Spring Boot |
| -------------- | ------- | ----------- |
| 개발 시간      | 측정    | 측정        |
| 코드량         | 측정    | 측정        |
| API 응답속도   | 측정    | 측정        |
| CPU 사용량     | 측정    | 측정        |
| Memory 사용량  | 측정    | 측정        |
| 동시 요청 처리 | 측정    | 측정        |
| 예외처리       | 비교    | 비교        |
| 유지보수성     | 분석    | 분석        |
| 프로젝트 구조  | 분석    | 분석        |
| AI 서버 연동   | 비교    | 비교        |
| 개발 편의성    | 분석    | 분석        |

목표:

> **동일한 사용자 경험을 제공하는 서비스를 Node.js와 Spring Boot로 각각 구현하고, 서버 구조와 성능 및 개발 경험의 차이를 비교한다.**

최종적으로 실험 결과를 바탕으로 Starry-Ocean에 적합한 Backend 구조를 선정한다.

# v4.6 — 실제 사용자 경험 최종 검증

최종 서비스 환경에서 사용자 경험을 다시 검증한다.

### 탐색

- 원하는 메모를 쉽게 찾을 수 있는가?
- Tree 메뉴가 도움이 되는가?
- 별이 많아져도 탐색 가능한가?

- 연결선이 너무 많지 않은가?

- AI 분석 결과가 사용자에게 실제로 도움이 되는가?

### 시각화

- 별이 과도하게 겹치지 않는가?
- 구역을 쉽게 구분할 수 있는가?

### 성능

- 메모 저장이 빠른가?
- AI 분석 대기시간이 적절한가?
- 대량 데이터에서도 서비스가 안정적인가?

# 핵심 개발 철학

Starry-Ocean은 단순히 많은 기술을 사용하는 것을 목표로 하지 않는다.

> **사용자 경험을 개선하기 위해 필요한 기술을 선택하고, 실제 데이터를 통해 그 선택이 적절했는지 검증한다.**

전체 개발 과정은 다음과 같다.

```text
사용자 경험 문제 발견
        ↓
기능 설계
        ↓
기술 선택
        ↓
기능 구현
        ↓
데이터 수집
        ↓
실험
        ↓
성능 / AI 분석
        ↓
최적값 도출
        ↓
실제 서비스에 반영
        ↓
테스트
        ↓
Linux / Docker / Cloud 배포
        ↓
사용자 경험 재검증
```

# 포트폴리오에서 강조할 핵심

## 1. 사용자 경험 중심 설계

AI가 생성한 모든 정보를 사용자에게 보여주는 것이 아니라, 사용자가 필요한 정보를 단계적으로 확인할 수 있도록 설계한다.

## 2. 대용량 메모 처리

10~500개 메모 데이터를 이용하여 데이터 규모에 따른 시스템 성능과 화면 사용성을 분석한다.

## 3. 최적 메모 개수

실험 결과를 기반으로 한 구역에서 적절한 메모 개수를 도출하고 실제 서비스에 적용한다.

## 4. AI 관계 시각화

주제, 감정, 키워드, 시간, 의미 유사도 등의 관계를 분석하고 사용자가 필요한 연결만 선택적으로 확인할 수 있도록 한다.

## 5. AI 임베딩 구조 비교

Node.js 내부 임베딩과 FastAPI 기반 AI 서버를 비교하여 서비스에 적합한 구조를 찾는다.

## 6. AI 모델 비교

Threshold 및 다양한 임베딩 모델을 비교하여 분석 품질과 성능 사이의 최적점을 찾는다.

## 7. 이미지 데이터 처리

텍스트뿐만 아니라 이미지가 포함된 메모를 처리하면서 DB 및 Object Storage의 차이를 분석한다.

## 8. 실제 서비스 환경 구축

Linux, Docker, Cloud 환경을 이용하여 로컬 프로젝트를 실제 서비스 환경으로 확장한다.

## 9. Backend 기술 비교

동일한 사용자 경험을 유지하면서 Node.js와 Spring Boot로 각각 구현하여 기술별 차이를 분석한다.

# 최종 목표

Starry-Ocean을 단순한 AI 메모 프로젝트가 아니라,

> **사용자 경험을 중심으로 AI 메모 시각화 기능을 설계하고, 실제 데이터를 기반으로 성능과 AI 분석 결과를 검증하며, Linux·Docker·Cloud 환경까지 확장한 실제 서비스형 프로젝트**

로 발전시킨다.

최종적으로는 **Node.js와 Spring Boot 두 가지 Backend 구조까지 직접 구현하고 비교하여, Starry-Ocean에 가장 적합한 기술 구조를 실험 결과를 통해 결정한다.**
