# Starry-Ocean 버전 업데이트 계획

## 1. 업데이트 방향

Starry-Ocean은 기존 기능을 단순히 추가하는 방식이 아니라,

> 기능 개선 → 데이터 실험 → 성능 분석 → 최적값 도출 → 실제 기능 반영 → AI 기술 비교 → 서비스 확장

순서로 발전시킨다.

---

# v2.1 — UX/UI 개선 및 사용성 강화

기존 Starry-Ocean의 기본 기능을 유지하면서 사용자가 서비스를 쉽게 이해하고 사용할 수 있도록 개선한다.

## 주요 기능

### 1. 튜토리얼 기능

처음 서비스를 이용하는 사용자를 대상으로 Starry-Ocean의 주요 기능과 사용 방법을 설명한다.

- 서비스 기본 개념 설명
- 메모 작성 방법
- AI 분석 방법
- 별과 구역의 관계 설명
- 메모 이동 방법
- AI 자동 배치 기능 설명
- Tree 메뉴 사용 방법

### 2. 별(메모) 이름 표시

기존에는 메모가 별 형태로만 표시되었다면, 별이 화면에 생성될 때 메모의 이름 또는 제목을 바로 확인할 수 있도록 개선한다.

목표:

- 별을 클릭하지 않아도 메모 구분 가능
- 많은 메모가 존재할 때 탐색 편의성 향상
- 사용자가 원하는 메모를 빠르게 찾을 수 있도록 개선

### 3. 구역 이름 표시

각 구역의 이름을 화면에 간단하게 표시한다.

예:

- 왼쪽 상단
- 오른쪽 하단
- 구역 중앙

등의 위치를 비교하여 가장 자연스러운 위치를 선정한다.

### 4. Tree형 보조 메뉴

화면 왼쪽에 보조 메뉴를 추가하여 구역별 메모 목록을 Tree 구조로 표시한다.

예:

Starry-Ocean
├── 구역 1
│ ├── 메모 A
│ ├── 메모 B
│ └── 메모 C
├── 구역 2
│ ├── 메모 D
│ └── 메모 E
└── 구역 3
├── 메모 F
└── 메모 G

기능:

- 구역별 메모 확인
- 메모 클릭 시 해당 별 위치로 이동
- 구역 클릭 시 해당 구역으로 이동
- 많은 메모를 쉽게 탐색할 수 있도록 지원

### 5. 메모 저장 + AI 분석 통합

기존의

`메모 저장`

`AI 분석`

두 개의 과정을 하나의 버튼 또는 하나의 사용자 흐름으로 통합한다.

기존:

메모 작성
→ 저장
→ AI 분석 버튼
→ 분석
→ 별 생성

개선:

메모 작성
→ 저장 및 AI 분석
→ 별 생성 및 배치

기존 방식과 통합 방식의 사용성 및 처리시간을 비교한다.

### 6. 예외처리 강화

다음과 같은 상황에 대한 예외처리를 추가한다.

- 빈 메모 입력
- 지나치게 긴 메모
- 잘못된 구역 ID
- 존재하지 않는 메모 ID
- DB 연결 오류
- AI 서버 오류
- 임베딩 생성 실패
- 중복 요청
- 네트워크 오류
- 잘못된 API 요청
- AI 분석 중 페이지 이탈

# v2.2 — 대용량 메모 데이터 실험

Starry-Ocean의 AI 자동 배치 및 임베딩 분석이 많은 메모에서도 정상적으로 동작하는지 검증한다.

## 1. 데이터셋 구성

다음과 같은 메모 데이터를 준비한다.

- 10개
- 30개
- 50개
- 100개
- 200개
- 300개
- 500개

가능하다면 실제 사용자가 작성할 법한 다양한 주제의 메모 데이터를 구성한다.

## 2. 데이터 규모별 분석

각 데이터 규모에 대해 다음 항목을 측정한다.

### 분석 성능

- 전체 AI 분석 시간
- 임베딩 생성 시간
- DB 처리 시간
- API 응답 시간
- 메모리 사용량
- CPU 사용량

### AI 분석 결과

- 생성된 그룹 수
- 메모 간 연결 수
- 유사 메모 그룹의 품질
- 관련 없는 메모가 연결되는 비율
- 하나의 그룹에 몰리는 메모 수

### 화면 사용성

- 별 겹침 정도
- 별 간 구분 가능 여부
- 화면 탐색 난이도
- 특정 구역의 과밀화 여부
- Tree 메뉴의 필요성

# v2.3 — 최적 메모 개수 도출 및 구역 제한

v2.2의 실험 결과를 바탕으로 하나의 구역에서 사용하기 적절한 메모 개수를 결정한다.

## 분석 예시

| 메모 수 | 분석 시간 | 별 배치 | 화면 복잡도 | 사용성 |
| ------: | --------: | ------- | ----------- | ------ |
|      50 |      측정 | 양호    | 낮음        | 양호   |
|     100 |      측정 | 양호    | 보통        | 양호   |
|     200 |      측정 | 확인    | 높음        | 확인   |
|     300 |      측정 | 확인    | 매우 높음   | 낮음   |
|     500 |      측정 | 확인    | 매우 높음   | 낮음   |

※ 실제 수치는 테스트 결과를 기록한다.

## 최적 메모 수 결정

실험 결과를 통해

> 한 구역에서 사용자가 탐색하기 가장 적절한 메모 개수

를 결정한다.

예:

`최대 100개`

또는

`최대 150개`

등의 기준을 설정한다.

## 실제 기능 반영

구역별 메모 개수를 표시한다.

예:

`현재 구역 메모 87 / 100`

제한에 가까워지면 경고를 표시한다.

예:

`현재 구역에 메모가 거의 가득 찼습니다.`

제한에 도달하면:

- 다른 구역으로 이동
- 새로운 구역 생성
- 기존 메모 정리

등을 안내한다.

# 포트폴리오에서 강조할 핵심 분석

## 1. 대용량 메모 처리

50~500개 메모를 이용하여 데이터 규모에 따른 성능 변화를 분석한다.

## 2. 최적 메모 개수

실험 결과를 바탕으로 한 구역에 적절한 메모 개수를 도출하고 실제 서비스에 적용한다.

## 3. AI 임베딩 구조 비교

Node.js 내부 임베딩과 FastAPI 기반 임베딩 서버의 성능 및 구조를 비교한다.

## 4. AI 모델 비교

Threshold와 임베딩 모델을 변경하여 Starry-Ocean에 적합한 AI 분석 방법을 찾는다.

## 5. 이미지 데이터 처리

텍스트 중심 서비스에서 이미지가 추가되었을 때 저장공간과 서버 성능에 미치는 영향을 분석한다.

## 6. 백엔드 기술 비교

Node.js와 Spring Boot로 동일한 기능을 구현하여 기술별 차이점을 분석한다.
